# Q-0486 — Native telemetry plot component with honest time and provenance

## Goal

Create a reusable, native PySide6 telemetry chart component that can later replace the weak Monitoring plot without modifying or integrating into Q-0477-owned files. This component visualizes only records supplied by its caller. It does not request data, infer medical status, or manufacture readings.

## Scope

- New module: apps/desktop/src/aetherion_desktop/telemetry_plot.py.
- One focused offscreen smoke/render harness and a GitHub Actions job that installs the already-required desktop dependency, runs the harness on Linux, and uploads the rendered preview.
- This Quest owns no existing module, shared localization catalog, Portal/main shell, server API, store, synthetic-patient module, NASA source, or existing test workflow.
- Do not add PyQtGraph: the desktop package currently declares PySide6 only, and this component can use native QPainter without expanding runtime packaging.

## Component contract

- Accept existing response-validated RecordedPoint-shaped objects (metric, value, unit, timezone-aware observed_at, source_id, scope, quality, verification) without importing or editing native_workspaces.py.
- Provide one shared UTC time-bounds/filtering contract so a host can pass the same filtered records to the chart and a table. Expose the bounds and filtered-record signal/API; keep filter behavior deterministic.
- Keep a metric/unit selection coherent; show numeric value ticks with the selected unit, readable UTC time ticks and explicit UTC labeling.
- Distinguish source IDs in a visible legend and distinguish READY, UNVERIFIED, and STALE point quality. Non-displayable states such as NO_DATA, OFFLINE, DENIED, and ERROR must not create chart points.
- Never connect through an unknown missing-data interval. Draw isolated points unless the caller explicitly supplies an allowed visual connection gap; this is a rendering rule only and must never be presented as a freshness or clinical threshold.
- Support useful nearest-point inspection with timestamp, value/unit, source, scope, quality and verification; include a crosshair. Provide time-range navigation/reset and pan/zoom where the native Qt implementation supports it.
- Follow the app palette using Qt palette inputs or an explicit palette adapter; keep contrast and point quality independent of decorative theme and never attach semantic meaning to color alone.

## Evidence and honest boundaries

- The smoke/render harness uses only deterministic, visibly labeled fictional engineering-preview records, with source ENGINEERING_FIXTURE, scope engineering_test, and verification TEST_FIXTURE / UNVERIFIED. It must not refer to the fixture as patient data, NASA data, sensor output, or a real measurement.
- Run the focused Linux/offscreen smoke, render an image, and retain the workflow artifact link and commit SHA in this Quest. The screenshot is a component preview, not native Windows or integrated Monitoring acceptance.
- Q-0477 remains the integration owner. Keep integration and Windows visual acceptance pending until the current owner releases the exact path through fresh Q-0477 CAS/owned-path metadata and an independent reviewer checks the integrated screen.
- Current narrow ownership request: Issue #8 comment https://github.com/huyng0699-arch/AETHERION/issues/8#issuecomment-6876546954. Do not edit apps/desktop/src/aetherion_desktop/native_workspaces.py, main.py, portal.py, i18n files, or QUEST_LOG.md.

## Acceptance

1. Native PySide6 widget renders a traceable time/value plot without adding a new plotting dependency.
2. UTC time and numeric value axes include units; source and quality are visible; point inspection preserves provenance.
3. Table and plot can consume exactly the same filtered record list and UTC bounds.
4. Unknown gaps remain visually disconnected by default; any explicit line-gap parameter is documented as visual-only.
5. The offscreen smoke runs against the real widget class, asserts filtering, quality, gap, and point-inspection behavior, and saves a visible preview artifact.
6. A separate reviewer inspects the code and artifact. Windows/native integration is not claimed by the isolated component Quest.
