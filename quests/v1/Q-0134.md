## Reproduced remote-catalog local-path vulnerability fix — 2026-11-14

- **Defect observed in previously committed code:** `BodyAtlas3D._got_catalog` previously used `self.models.setdefault(ident, dict(item))` on a network JSON record; this retained network-supplied `resolved_path`. `BodyAtlas3D._select` then called `_render(Path(path), ...)` for **any existing path**, without an approved asset-root or current SHA check. A server catalog field could thus steer native VTK toward an arbitrary local file. This is a source-confirmed local-path injection/reproducible trust-boundary flaw, not an observed real attack; no patient data was used.
- **Fixed** in `atlas3d.py`, [commit d038cee41b7380a6265c9164e2e054256976d914](https://github.com/huyng0699-arch/AETHERION/commit/d038cee41b7380a6265c9164e2e054256976d914), verified Git blob **`e08db8a5121b944b3146acf732aa6e5d1abfaa7e`**: a strict allowlist of source/rights/technical model metadata is copied from the remote catalog **without `resolved_path`**; remote file selection continues solely through the existing app-owned download cache and SHA check. A local path must now pass `verified_local_model_file(meta, ASSETS)` immediately before native `_render`; invalid/untrusted direct files return the real `invalid` state and are **not rendered**. Source inspector additionally passes the actual assets root, not an arbitrary caller path.
- **Defense helper** in `render3d/source_inspector.py`, [commit 57c3447c0b3a080e0ea28320003bc1d9e61d2a83](https://github.com/huyng0699-arch/AETHERION/commit/57c3447c0b3a080e0ea28320003bc1d9e61d2a83), verified Git blob **`862400e4456feacedb925afc844a5c8faccd9d01`**.
